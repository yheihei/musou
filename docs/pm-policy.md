# musou の PM 方針

2026-10-16 の本人の委任に基づき、2026-10-17 から運用する。
PM は Codex、開発は Claude、遊んだ感想と根本方針の判断は本人が担当する。
読み取り専用の PM 運用は一旦停止し、PM が判断を対象 Issue に返して開発を進める。

## ゲームの軸

- 三國無双7/8のように、大勢の敵を一度に派手に薙ぎ払い、撃破数が勢いよく伸びる爽快感を最優先にする。
- 戦況を有利にして無双できる流れを作る。士気・味方軍団との共闘・拠点のつながり・秘計が有利に働き、工夫して勝てる奥行きを残す。
- 敵の士気が高いと敵も拠点も手強く、勢いを作れば楽に倒せる。拠点をつながず敵の多い場所へ孤立して無理攻めしても、簡単には落とせない。
- 大人が遊んでやや簡単と感じる程度を目指す。ボスはカービィ ディスカバリー程度の工夫と歯ごたえを残し、単なる高 HP や複雑な説明で難しくしない。

攻撃の操作と戦場ルールの具体形は [設計メモ](design.md) を参照する。
三國無双6・6 Empires を参照した既存の仕組みは、上の体験を実現する手段として扱う。
同時に倒せる数、撃破のペース、士気差と強行攻略の難しさ、ボスの対処のしやすさを、1人と散開した複数人で確かめる。合格する具体的な値は検証から決め、未計測の値を達成済みとしない。
数値バランスの実値は引き続き `src/shared/Config.luau` に置く。

## PM が決めること

PM は可逆な仕様の詳細・仮数値・UI と演出・優先順・検証条件を、ゲームの軸に沿って決める。
毎回本人へ選択を戻さず、結論と理由を示して開発を進める。
本人の新しい直接指示を優先し、本人の決定・PM の判断・未検証の仮説を分けて記録する。

- 既承認の Humanoid 採用、[#91](https://github.com/yheihei/musou/issues/91) の先行、秘計の重複禁止を尊重する。
- [#142](https://github.com/yheihei/musou/issues/142#issuecomment-6188626711) の伊賀の明るい青・4クランの共通形状とリグ、[#82](https://github.com/yheihei/musou/issues/82#issuecomment-6157428482) の味方比率等の承認済み判断を蒸し返さない。
- ゲームの根本や、大規模で戻しづらい変更は本人へ相談する。既承認の根本方針を変える場合も含む。
- 支払い、公開・配信、認証・権限・セキュリティの変更、復元不能な削除は、この委任では許可されない。
- VLCNP の 2 時間・1 ticket 制限は musou に適用しない。

本人の感想は、PM が必要な Issue の作成・追記、優先度、完了条件、マイルストーンに整理する。
既存 Issue を先に探し、同じ課題を重複して起票しない。

## Issue への返し方と開発への受け渡し

判断は `yheihei/musou` の対象 Issue に、次の形で記す。

```text
PM判断（Codex、日付）
結論: 採用する内容と範囲
理由: ゲームの軸、本人の指示、既存仕様や検証結果との関係
次作業: 開発で進める内容と、残す依存・未確認事項
確認条件: 完了とする条件、必要な環境、結果の記録先
```

本人の発言や承認を装わない。実装済みでも確認待ちなら、その状態を明記する。
Claude は開始時に最新の本人指示、`AGENTS.md`、本書、対象 Issue の本文と最新コメントを読み、PM 判断を取り込んで進める。
既存開発に割り込む二重起動はしない。Issue への投稿だけで実行が再開したとは扱わず、次の既存実行の結果で反映を確認する。

## 平日と土曜の進め方

- 平日は PM が判断待ちを解消し、Claude が既存の開発実行で進める。
- 既存の 07:30 枠では前日までの判断待ちと優先順位を整理し、09:45 枠では開発結果と新しい判断を対象 Issue へ返す。土曜の準備も既存枠に含め、新しい予定は追加しない。
- 土曜日は本人が約30分、自由プレイと重点最大3件を確認し、この会話へ感想を伝える。通しプレイがまだできなければ、その時点で動く部分だけに絞る。
- PM は土曜の重点ごとに、対象、試し方、見たい体験・挙動、現在の制約を短く準備する。本人の感想を次の判断と開発へつなぐ。

本書はスケジュール設定や開発ルーティンの停止・再開を変更するものではない。

## 確認と完了の扱い

結果は、実装、ローカルのチェック、該当 SHA の CI、Studio、実際の複数人、スマホ実機を別々に記す。
CI 成功や窓口の値の一致を、爽快感・画面の良さ・通しプレイの確認の代わりにしない。
Studio の複数クライアントと、実際に複数人で遊ぶ確認も分ける。

Studio と Rojo は [AGENTS.md](../AGENTS.md) の手順と権限を守る。
[#177](https://github.com/yheihei/musou/issues/177#issuecomment-6166846015) は NOT_PLANNED であり、自動起動・自動接続の許可として扱わない。
画面操作が必要な作業は Issue に残し、許可された会話で扱う。
Git 外で管理するマップのプレース保存や、未確認の項目を完了扱いしない。残件は同じ Issue または追跡先に明記する。

マーケティングの相談は [軍配相談メモ](marketing.md) の範囲を維持し、本書から公開や配信の許可を広げない。
