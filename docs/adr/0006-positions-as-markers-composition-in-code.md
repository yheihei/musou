# 位置はプレースの目印に、構成はコードに置く

ステージの拠点・部隊・上忍・首領の初期配置を、位置と構成に分けて持つ。
位置と形はプレースに置いた目印で表し、構成はコード（`src/shared` のステージごとの配置の定義）に書く。
構成とは、拠点の種類と初期の所属、拠点どうしのつながり、部隊を率いる上忍と方針、兵数などを指す。
マップは Git の管理外でプレースを直接直すため、地形と一緒に動く位置は目印に任せる。
進行を左右する構成は、差分をレビューでき Lune でテストできるコードに置く。

## 目印の形式

目印はすべて区画のフォルダの下に置き、読み込むのは出撃する区画の目印だけにする。

| 目印 | 置き場所 | 名前 | パーツで表すもの | Attribute |
|---|---|---|---|---|
| ロビー | `Workspace.Lobby` | `SpawnLocation`（プレースで唯一） | ロビーへの出現位置 | なし |
| 区画 | `Workspace.Stages` の下のフォルダ | 区画名（`Iga1`、`Test` など） | なし（フォルダ） | なし |
| 区画の範囲 | `<区画>.Mejirushi.Bounds` | `Bounds` | 区画の中心・大きさ・向き | なし |
| 出撃地点 | `<区画>.Mejirushi.ShutsugekiChiten` | `1`〜パーティーの上限人数 | 立つ位置と向き | なし |
| 拠点と本陣 | `<区画>.Mejirushi.Kyoten` | 拠点 ID | 拠点の範囲の中心・大きさ・向き | なし |
| つながりの道筋 | `<区画>.Mejirushi.Tsunagari` の下のフォルダ | `1`、`2` と進む順の経由点 | 経由点の位置 | フォルダに `KyotenA`・`KyotenB` |
| 落石地点 | `<区画>.Mejirushi.RakusekiChiten` | 地点 ID | 岩を落とす位置 | `KyotenA`・`KyotenB` |
| 大火計地域 | `<区画>.Mejirushi.DaikakeiChiiki` | 地域 ID | 範囲の中心・大きさ・向き | なし |
| イベントシーンのカメラ | `<区画>.Mejirushi.EventScene.<シーン ID>.Camera` | ショットの名前 | カメラの位置と向き | なし |
| イベントシーンの役者 | `<区画>.Mejirushi.EventScene.<シーン ID>.Yakusha` | NPC はキャラクター ID、出撃したプレイヤーは `Player1`〜`Player4` | 立ち位置と向き | なし |

- `KyotenA`・`KyotenB` は、つながりや落石地点の両端の拠点 ID（文字列）
- つながりの経由点は `KyotenA` から `KyotenB` へ名前の順にたどり、逆向きは逆順にたどる
- つながりのフォルダ名は読みやすさのためだけに付ける（`IgaHonjin-Monzen` など）。照合には使わない
- 目印のパーツにはタグ `Mejirushi` を付け、`Anchored` を true、`CanCollide`・`CanTouch`・`CanQuery` を false にする
- 保存時は編集しやすいよう半透明にしておき、サーバーが起動時にタグ `Mejirushi` のパーツを透明にする
- 目印は地面の高さに合わせて置く。出現させるときは地面の高さの共通関数で合わせ直す
- Attribute には ID と参照だけを置き、兵数・時間・威力・半径などの数値は `Config.luau` に置く
- ロビーの `SpawnLocation` 以外に `SpawnLocation` を置かない。出撃地点は目印のパーツで表す
- 区画どうしとロビーは `StreamingTargetRadius` 以上離す
- 建物など目印以外のものは、区画のフォルダの下に自由に置いてよい

## 構成に置くもの

- 拠点の一覧（拠点 ID、通常拠点か本陣か、初期の所属の軍）
- つながりの一覧（両端の拠点 ID）
- 部隊の一覧（率いる上忍、方針、初期の拠点 ID、兵数を引く `Config.luau` の項目）
- 首領は `Stages.luau` の両軍の首領を引き、本陣の拠点から出す

構成にあって目印が無い拠点・つながり、目印にあって構成に無い拠点・つながりは、読み込み時に警告を出す。
落石地点と大火計地域は、場所の形だけで決まるため目印だけで完結させる。
そのため、地点の追加と移動はプレースの作業だけで済む。
参照する拠点の実在とつながりの有無は、読み込み時の検証で確かめる。

## 試験用区画

- 試験用区画 `Test` は、平らな床と出撃地点だけをプレースに保存する
- 拠点などの目印は、試験用ステージの定義（コード）に位置を持たせる
- 窓口のコマンドでテストプレイ中に目印を生成し、保存しない
- 試験用ステージの位置が区画の範囲に収まることは Lune でテストする

## Considered Options

| 観点 | 案1 位置も構成もコード | 案2 位置も構成も目印と Attribute | 案3 位置は目印、構成はコード（採用） |
|---|---|---|---|
| Git の差分 | 全部残る | 何も残らない | 構成は残り、位置は残らない |
| Lune のテスト | 全部テストできる | 実行時の検証しかできない | 参照・つながり・開始時の孤立をテストできる |
| マップ修正への追従 | 地形を直すたびに座標を手で直す | 目印が地形と一緒に動く | 目印が地形と一緒に動く |
| 並行作業 | コードの衝突だけで済む | 構成の変更もプレースの作業待ちになる | 構成はコードで並行でき、位置だけプレースの作業待ち |
| 規約との整合 | 座標という数値が `Config.luau` の外に増える | 兵数などを Attribute に置くと数値の規約に反する | 数値は `Config.luau`、形は目印に分かれる |

## Consequences

- 拠点を1つ足すには、構成の追加と目印の追加の両方が要る
- 位置の変更は PR の差分に出ない。マップの issue では俯瞰の画像と地点の一覧を issue に残す
- 同じプレースを書き換えるマップの作業は、並行させず1件ずつ進める
