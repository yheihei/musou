# 下忍の描き方の試作（#5）

検証用ブランチ `kensho/genin-byoga` だけに置く。main には入れない。
案A（サーバーの Humanoid）と案B（クライアントで描く）を、同じ動きで比べる。
案B の送り方は、Attribute と UnreliableRemoteEvent の2つを試す。
調査の要点は [docs/research/genin-byoga.md](../docs/research/genin-byoga.md) にある。

## 作り

| 場所 | 中身 |
|---|---|
| `proto.project.json` | 計測用のプレース（平らな床と出現地点）。本番のサービスは入れない |
| `proto/server` | 方式と体数の切り替え、案A、案B の計算と送信、自動の薙ぎ払い |
| `proto/client` | 計測の画面と、案B の下忍の描画 |
| `src/shared/Proto` | 案B の下忍の計算（`GeninSim`）と、buffer への詰め方（`Snapshot`）。Lune でテストする |
| `src/shared/Config.luau` | `GeninProto` 節（体数の候補、動きの値、送る回数） |

下忍の動きは3つの方式でそろえる。

- プレイヤーに近づき、間合いで攻撃する（胴の色が赤くなる）
- 自動の薙ぎ払いで外へ吹き飛ぶ（2秒ごとに半径 14 スタッド）
- 2回当たると倒れ、1.5 秒後に消えて、1 秒後にプレイヤーの近くへ湧き直す

## 計測の手順

1. `rojo build proto.project.json -o genin-proto.rbxl` でプレースを作る
2. Studio で開き、テストプレイで3つの方式が動くことを確かめる
3. 新しい体験として公開し、非公開のままにする（本番の体験には公開しない）
4. スマホで公開した体験に入り、「カメラ固定」を ON にする
5. 左上のボタンで方式と体数を切り替え、切り替えてから 10 秒ほど待つ（湧かせた直後は通信が増える）
6. 方式と体数ごとに、画面の FPS・受信・サーバーの Heartbeat・メモリを #15 に記録する

画面のボタンは次のとおり。

- 方式は「案A Humanoid」「案B Attribute」「案B Unreliable」
- 体数は 30・60・100
- 自動の薙ぎ払いの ON と OFF
- カメラ固定の ON と OFF（プレイヤーの斜め上から見下ろす。下忍がカメラに当たって寄る動きを無くし、方式どうしの描画の量をそろえる）

計測のときの注意

- 「薙ぎ払いで当てた数」が方式どうしで同じくらいかを見る（案A は撃破のたびにモデルを複製し直すので、撃破の頻度で受信量が変わる）
- メモリは方式ごとに入り直して測る（案A から切り替えても下がりきらない）
- Studio では開発者コンソール（F9）のネットワークの統計も見る
